# 모의고사 시험보기 프로그램 — 학생용 모의고사 응시 웹앱

## 프로젝트 개요
학생이 실제 모의고사 PDF의 문제를 **원본 그대로(이미지)** 1문제씩 풀어보는 웹앱.
교사가 PDF를 업로드하면 문항을 자동으로 잘라 이미지로 만들고, 정답을 입력해 게시하면
학생이 링크로 들어와 응시한다. 학생 학습 흐름(단어암기 → **시험보기** → 문법학습) 중
"시험보기" 자리를 채우는 신규 프로그램. 기존 `모의고사_프로그램`(PDF→AI 태깅→문제은행
구축, 교사 전용 파이프라인)과는 별개이며 통합하지 않음 — 이 프로그램은 학생이 직접
쓰는 화면이라는 점이 다름.

## 기술 스택 / 구조
- **단일 파일**: `index.html` (VocaTest와 동일한 관습 — 빌드 도구 없음, Tailwind Play CDN,
  브라우저에서 바로 열면 실행). `?session=KEY`가 있으면 학생 화면, 없으면 교사 화면.
- **PDF 처리**: pdf.js(CDN, `cdnjs.cloudflare.com/.../pdf.js/3.11.174/`) — 브라우저에서
  PDF를 캔버스에 렌더링하고, `getTextContent()`로 텍스트 좌표를 읽어 문항 경계를 찾음.
- **백엔드**: `sheet_backend.gs` (Google Apps Script + 스프레드시트 + Drive).
  VocaTest·모의고사_프로그램과 동일한 무료 백엔드 패턴 재사용.

## 왜 VocaTest처럼 "링크에 데이터 다 담기" 방식이 아닌가
문항이 **이미지**라서(지문·도표·특수기호를 원본 그대로 보존하려고 텍스트 추출 대신
캡처 방식을 선택함) 용량이 커서 URL에 못 담음. 그래서 이미지는 Google Drive에 올려두고,
학생에게 주는 링크(`?session=KEY`)는 그 시험의 짧은 식별자만 담음 — 실제 데이터(이미지
URL 목록·정답)는 전부 서버(구글시트)에서 조회.

## 데이터 흐름
1. **교사 — PDF 업로드 → 자동 문항 분리**: pdf.js로 페이지 렌더링 + 텍스트 좌표에서
   문항번호(`18번`, `18.` 패턴 — `모의고사_프로그램/exam_tagger.py`의 `HEADER_PATTERNS`
   아이디어를 참고해 JS로 새로 작성, 파이썬 코드를 가져다 쓰지는 않음) 위치를 찾아 문항별
   y좌표 경계를 계산하고, 그 구간만큼 캔버스를 잘라 JPEG 이미지로 만든다.
2. **경계선 보정 UI**: 자동 분리가 틀렸을 때를 위해 처음부터 포함. 문항 사이 경계선을
   마우스로 드래그해 위치를 조정하거나, 경계를 추가/삭제해 문항을 나누거나 합칠 수 있음.
3. **정답 입력**: 문항마다 객관식 ①~⑤ 라디오로 정답 지정.
4. **게시**: 이미지들을 `doPost(action:'uploadImage')`로 업로드(POST+no-cors라 응답 못
   읽음) → `doGet(action:'imageStatus')`를 JSONP로 폴링해 Drive 업로드 완료 확인(VocaTest의
   `storeShortLinkPayload` "POST 후 짧은 GET으로 재확인" 패턴과 동일) → 전부 확인되면
   `doPost(action:'saveExam')`로 시험 메타데이터(문항 순서, 이미지 URL, 정답) 저장.
5. **학생 응시**: `?session=KEY`로 접속 → `doGet(action:'fetchExam')`으로 이미지 URL
   목록만 받음(**정답은 서버에서 절대 클라이언트로 안 내려줌** — 채점은 서버 쪽에서).
   이름 입력 후 문항 1개씩 이미지+①~⑤ 버튼 표시. 문항이 뜬 시각과 답을 고른 시각의
   차이를 그 문항의 소요시간으로 기록 — **학생 화면에는 시간이 전혀 노출되지 않음**.
   마지막 문항까지 마치면 `doPost(action:'submitResult')`로 답+시간을 전송, 서버가
   정답과 대조해 점수를 계산해 시트에 기록.
6. **교사 결과 대시보드**: `doGet(action:'listResults')`(토큰 필요)로 그 시험 응시자
   목록(이름/점수/총시간)을 받고, 학생을 클릭하면 문항별 정답여부+소요시간 표를 펼쳐
   보여줌. **자동 분석/코멘트는 만들지 않음** — 교사가 눈으로 보고 직접 판단하도록 데이터만
   정리해서 보여주는 게 목적(요청사항).

## 시트 구조 (`sheet_backend.gs`)
- `Exams`: examKey / title / range / questionCount / answersJson / imageUrlsJson / createdAt / expiresAt
- `ExamImages`: imageKey / url / savedAt (업로드 확인용 임시 매핑)
- `ExamResults`: date / examKey / name / score / totalTimeMs / answersJson / timesJson

## 중요한 설계 결정 · 제약
- **문항은 전부 객관식(①~⑤)만 지원**. 서술형/직접입력형은 범위 밖(필요해지면 별도 논의).
- **정답은 클라이언트에 절대 노출 안 함** — `fetchExam` 응답에 answers 필드 없음, 채점은
  Apps Script(`handleSubmitResult_`) 서버 쪽에서 수행.
- **문항 소요시간은 학생 비공개, 교사만 결과 탭에서 확인**. 학생 화면 어디에도 타이머
  UI를 넣지 않음(요청사항 — 몰래 재는 것처럼 보이지 않게, 그리고 학생이 시간에 쫓기지
  않도록).
- 이미지 업로드는 Drive에 저장하고 `uc?export=view&id=...` 형태 URL로 `<img>` 태그에서
  바로 embed 가능하게 함(폴더 공유 아니라 파일 단위로 "링크가 있는 모든 사용자" 권한).
- `모의고사_프로그램`(PDF→AI 태깅→구글시트 문제은행)과는 통합하지 않기로 결정 — 그건
  교사 전용 콘텐츠 준비 파이프라인이고, 이 프로그램은 학생이 실제로 접속해 쓰는 화면이라
  용도가 다름.

## 구현 상태
1차 버전 완료(`index.html` + `sheet_backend.gs`). 가짜 데이터로 교사 쪽 전체 화면 흐름
(업로드→경계보정→정답입력→게시 게이트→설정→결과 빈 화면)과 학생 쪽 전체 흐름
(이름입력→문항1→문항2→제출완료)을 브라우저에서 실행해 콘솔 에러 없이 동작 확인함.
**아직 검증 못 한 것(사용자가 직접 해봐야 함)**:
- 실제 PDF 업로드 시 pdf.js 자동 문항 분리가 실제로 정확히 되는지(자동화 브라우저 툴은
  파일 선택 다이얼로그를 조작할 수 없어서 더미 캔버스로만 크롭/보정 로직을 검증함).
- `sheet_backend.gs`를 실제 구글시트에 배포해서 이미지 업로드(Drive)·시험 저장·결과 제출·
  결과 조회가 실제로 동작하는지(Apps Script 배포는 사용자 구글 계정이 필요해 이 세션에서
  못 해봄).

## 발견하고 고친 버그
- **학생 화면이 웹훅 URL을 못 찾는 문제**: 처음엔 `deliveryCfg()`(교사 브라우저의
  localStorage)를 학생 쪽에서도 그대로 읽으려 했는데, 학생은 다른 기기/브라우저라 그 값이
  없음 → 링크에 `&hook=웹훅URL` 파라미터로 실어 보내고 학생 쪽은 그 파라미터를 쓰도록 수정.
- **정답 입력 화면에서 시험 이름표가 사라지는 문제**: 정답 버튼을 누르면 `AnswerStep`이
  전체를 다시 그리는데, `#as-title` 입력값이 draft에 반영되기 전이면 다시 그릴 때
  빈 값으로 리셋됨(VocaTest가 예전에 겪었던 것과 같은 종류의 버그) → `input` 이벤트에서
  바로 `draft.title`/`draft.range`에 반영하도록 수정.

## 다음에 사용자가 해야 할 일
1. 구글시트 새로 만들고 `sheet_backend.gs` 배포(README 없음 — 파일 맨 위 주석에 설치
   순서 적어둠), 스크립트 속성에 `TOKEN` 등록.
2. `index.html`을 실제 http(s) 호스팅(GitHub Pages 등)에 올리기 — VocaTest와 동일한 이유로
   `file:///` 로컬 경로에서 만든 링크는 학생 기기에서 못 엶.
3. 설정 탭에서 웹훅 URL/토큰 입력 후, 실제 PDF로 시험 만들기 전체 흐름을 한 번 끝까지
   테스트(문항 분리 정확도, 이미지 업로드, 학생 응시, 결과 대시보드).
